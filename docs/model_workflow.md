编写日期：2026-11-18

实现更新：已增加Windows/Python 3.10支持、统一准备入口、CatBoost适配与剩余时长对照配置；实际执行状态见本机JSON报告。

用途：明确候选模型在项目中的职责、接入顺序和评价方式，作为后续开发与实验的路线说明。

当前阶段：截至2026-11-19，已完成第6轮成熟历史下限双窗口对照。LightGBM＋校准＋历史下限是当前开发A最优候选（167.34／151.27），同样增加历史下限的简单方案为171.84／155.11。收益伴随承诺时长和MAE增加；最终方案未冻结，最终留后锁定。最新结果见[第6轮报告](mature_history_floor_results.md)，历轮记录见[《代码、首轮结果与改进记录》](code_and_results_review.md)。本文中的后续方案不构成扩大训练范围的授权。

## 1. 建议采用的模型组合

初始设计以LightGBM为包裹级主线、CatBoost为第一对照、TabM为可选探索。第6轮以**LightGBM＋校准＋成熟历史下限作为当前开发A最优候选**，保留获得相同历史信息的承运商方案作为简单对照。CatBoost已测但未获增益，暂不扩展神经网络。XGBoost和FT-Transformer仍为备选，DeepETA主要提供建模思路。

每个模型的作用是回答一个明确问题：

| 模型或组件 | 在后续流程中的作用 | 要回答的问题 | 当前代码状态 |
|---|---|---|---|
| B0 全局常数、B1 承运商常数 | 建立参照，检查复杂模型是否值得采用 | 包裹级特征是否带来稳定增益？ | B1已完成dev_1；B1＋校准已完成两个窗口；B0未真实运行 |
| M1 LightGBM Q90/Q97 | 主模型，提供包裹级尾部时效预测 | 共有字段能否改善承诺时效与尾部覆盖？ | 已完成dev_1真实回测；见结果复盘 |
| M2 LightGBM＋承运商残差校准 | 调整不同承运商的系统性偏差 | 独立校准能否改善严格版 A？ | 已完成两个窗口，A为421.53／341.90 |
| CatBoost 分位数回归 | 第一替代模型，对照类别字段处理方式 | 更换类别字段处理方式能否改善预测？ | 已完成两个窗口，A为435.11／341.90，未获增益 |
| TabM＋双分位数输出 | 检验神经网络表示及其与树模型的互补性 | 不同表示方式能否改善两个开发窗口的结果？ | 待接入；分位数输出需适配 |
| XGBoost 分位数回归 | 另一种树模型对照 | 替换树学习方法是否有额外收益？ | 备选 |
| FT-Transformer＋双分位数输出 | 研究字段间注意力交互 | 注意力是否优于较简单的神经网络？ | 备选；分位数输出需适配 |
| 历史统计特征 | 为各模型提供时点正确的业务背景 | 改善来自新增信息，还是模型结构？ | 待实现 |
| 成熟历史下限后处理 | 以截至C已签收的较老记录补充尾部信息 | 保守下限能否降低分组覆盖罚分，代价多大？ | 两个窗口已完成；A改善，MAE变大；未加入树模型特征 |
| DeepETA 思路 | 指导基础估计、残差修正与分组调整 | 能否用业务结构简化预测任务？ | 参考方案，不是现有模型 |

优先级是工程判断，不是性能排名。最终选择依据固定开发窗口的实际结果。

## 2. 赛题条件决定模型目标

依据 F4 资料包说明，训练集包含约526.7万条已完成履约记录，测试集包含约91.1万条记录。单包预测只能使用测试集共有的23个字段；包裹编号不进模型，首版排除邮编。

所有包裹目的地均为美国。州、城市、机场等字段是匿名类别，编码数字没有大小、距离或经纬度含义。因此优先考虑承运商、渠道、仓库、目的州和城市之间的交互，不把“承运商×目的国”视为新增区分信息。

决策时点是订单流入时间 `issue_time`，预测目标是支付到签收的总小时数。严格版 A 的分数越低越好：

```text
ME = abs(mean(预测时长) - mean(真实时长))
准时罚分 = 500 × 各承运商 max(0, 0.90 - 准时率) 之和
严重超时罚分 = 500 × 各承运商 max(0, 严重超时率 - 0.03) 之和
A = ME + 准时罚分 + 严重超时罚分
```

严重超时指实际时长比承诺时长多24小时以上。ME不是逐包MAE，各承运商罚分也不按样本数加权。因此，选模型不能只看平均误差，小承运商的覆盖表现同样需要检查。

当前代码采用以下初始决策规则：

```text
承诺时长 = max(Q90, Q97 - 24小时)
```

Q90和Q97分别对应两项覆盖目标。这个规则是合理起点，但不保证官方总分最优，也不保证时间分布变化后的覆盖率。模型预测后仍需独立校准与评估。

## 3. 各候选模型如何接入

### 3.1 LightGBM：建立可复现的主线

现有代码已串联特征、两个分位数模型、校准、官方评分核对和产物保存。后续首先利用这条主线建立可信结果，再替换模型。

首轮已在相同dev_1切分比较B1、M1、M2；B1＋同样校准的对照也已获后续授权并补跑，在dev_1优于M2，说明复杂模型的额外收益尚未得到支持。不能同时改模型、切分和特征后，把全部提升归因于模型。

### 3.2 CatBoost：检查类别信息是否利用充分

CatBoost适合作为第一对照，因为F4包含较多匿名类别。首轮使用与LightGBM相同的信息、目标及校准协议，保留CatBoost自身的类别处理方式；不要求不同算法使用完全相同的数值编码矩阵。

可以分别训练Q90与Q97，或评估MultiQuantile。官方文档当前列出Quantile支持GPU、MultiQuantile不支持GPU，实施时应根据锁定的软件版本确认支持范围。[参考1]

预期产出是与主线可直接比较的分数、分组诊断、耗时和内存记录。若没有稳定优势或误差互补性，不因模型名称不同而保留它。

### 3.3 TabM：检验神经网络路线

TabM通过参数共享实现类似多个MLP的集成，是表格神经网络候选。[参考2] F4版本拟采用：

```text
共有字段及可用历史统计
    → 类别/数值表示
    → TabM
    → Q90和Q97输出
    → 独立承运商校准
```

需要自行适配双分位数输出、分位数损失、未知类别和分位数交叉处理；不能直接沿用普通均方误差回归并宣称满足覆盖目标。

TabM的价值在于检验不同表示是否有益。融合只是后续候选：只有固定开发窗口显示误差互补时才值得尝试，融合之后仍需重新校准和评估。

### 3.4 XGBoost与FT-Transformer：有明确问题时再接入

XGBoost支持分位数目标，官方示例建议使用hist方法，并提醒可能出现分位数交叉。[参考3] 它适合检验另一种树模型能否改善尾部误差。

FT-Transformer把字段转换成向量并学习字段交互。[参考4] 它适合在已有小型MLP或TabM对照后，检验注意力是否值得增加训练成本。首轮不同时铺开全部候选。

## 4. 比替换模型更先值得比较的两项设计

### 4.1 总时长预测与剩余时长预测

现有方案直接预测总时长。另一个候选是：

```text
已过时长 = (issue_time - pay_time) / 1小时
剩余时长标签 = y_total_hours - 已过时长
总时长分位数预测 = 已过时长 + 剩余时长分位数预测
```

已过时长在决策时已知，可以让模型专注于未来履约部分。这里是给定当前包裹信息后的确定量相加，并非把多个不确定环节的分位数直接相加。

这只是待验证的建模方式，不保证比直接预测总时长更好。先审计时间倒挂、缺失和异常；明确处理规则，不能为方便拟合静默删除样本或把负时间差视作正常耗时。

### 4.2 历史基准与残差修正

DeepETA以路由引擎ETA为基准，再预测修正量，并处理不同业务分组的偏差。[参考5] F4没有路由引擎，可考虑用历史业务统计构造基准：

```text
已过时长 + 历史剩余时长基准 + 模型修正量
```

历史基准优先使用承运商、承运商×渠道、仓库、目的州等分组，保存样本数并为稀疏组合设置回退。可以进一步研究历史环节耗时，但43个节点仍不能作为当前包裹的输入；缺失节点也不等于耗时为零。

每个训练样本的统计只能来自其决策时已可用且属于允许来源的历史记录；默认仅使用对应fit来源，最终留后永远排除。缓存绑定数据摘要、split_id、统计参数与标签截止。不能先用整个训练表的标签计算分组统计再回填。

Uber拥有经纬度、路网与交通输入，F4只有匿名地理类别，因此不直接照搬地理网格编码。其网络内偏置层也不等同于本项目独立校准集上的残差校准。

当前已完成A、B及C的部分接口，并在明确授权范围内完成D的dev_1首轮、dev_2三组复核及E中的CatBoost双窗口对照。其他新对照、最终留后与最终预测不因本文获得授权。

官方资料允许测试预测使用全部训练数据，但项目目前保持最终留后隔离。最终离线拟合的标签截止和是否使用留后记录，应在开发结束后另行明确；不得把该规则用于放宽开发验证。

## 6. 如何判断一个模型值得继续

真实实验仅在明确授权范围内执行。对照使用相同split_id、固定开发评估键、相同数据版本和标签可用协议；类别字典只从拟合数据建立。新模型不获得更宽松的标签或特征权限。

每次实验至少记录：

| 记录项 | 用途 |
|---|---|
| 两个窗口各自的A、B、ME和两项罚分 | 避免只看单个总分；主选型依据是A |
| 每个承运商的样本数、准时率、严重超时率、平均预测时长 | 定位分组短板及过度保守问题 |
| 拟合/校准标签截止与校准成熟比例 | 判断慢件选择偏差是否影响结论 |
| 未知类别及稀疏组回退情况 | 解释新渠道或新区域的行为 |
| 运行时间、峰值内存与模型大小 | 判断本机运行成本 |
| 配置、代码、数据和键摘要 | 保证结果可复查 |

窗口级与承运商级结果均保留，不只报告两个窗口的平均值。若改进集中在一个窗口、另一个明显退化，应检查漂移和校准原因；不能移动日期或删除重叠样本来改善成绩。最终留后不用于选模型、调参、早停或校准。

当前训练集只有最终已完成且满足时效范围的记录，不是完整的删失队列。标签成熟度检查可以揭示风险，但不能恢复缺失慢件，也不能因此声称获得无偏尾部估计。生存分析暂不列入第一轮模型对照。

## 7. 实现位置、算力与最小检查

核心逻辑放在`src/f4/`，CLI放在`scripts/`，候选参数放在`configs/experiments/`。目标转换位于`src/f4/targets.py`，CatBoost适配位于`src/f4/models.py`，统一准备入口为`scripts/run_preparation.py`；历史统计特征和TabM仍为后续工作。

统一记录模型族、预测目标、特征版本和校准方式，并沿用：

```text
artifacts/runs/<run_id>/   模型、编码器等
outputs/runs/<run_id>/     预测
reports/runs/<run_id>/     配置、来源、分数、分组诊断、资源报告
```

split_id独立于run_id，已有实验禁止覆盖。共享缓存不每轮复制。数据、模型、预测和本机运行报告继续按.gitignore留在本机。

本机16GB内存下，树模型先使用CPU、最多4线程，窗口和模型串行，避免把67列原始字符串全部装入内存。CatBoost高基数类别组合及历史统计都需控制规模并实测内存。

神经网络可将小型配置与单张8—16GB显存GPU作为初步实验预算，实际占用取决于类别数量、网络宽度和批大小；这是工程估计，不是已验证的最低配置或训练时长承诺。当前尚未核实本机GPU。

只增加与改动有关的检查：键与顺序、未知类别、来源与时间隔离、目标转换往返、分位数输出及保存加载、官方评分一致性、必要的合成端到端冒烟。合成结果不作比赛成绩；LightGBM遵守最多200行、5轮、单线程限制。其他新增模型也采用独立的小型合成配置，不借冒烟入口拟合真实F4数据。

## 8. 当前建议与下一步

本机环境、数据准备、切分、三条主路线对照及成熟历史下限实验已完成。新LightGBM候选在两个窗口改善A，但约96%的预测被下限抬高，说明收益主要来自更保守的历史承运商承诺。下一步检验能否在保持分组覆盖的同时缩短承诺，不继续盲目更换模型。剩余时长尚未真实运行，树模型历史输入特征及神经网络尚未接入；扩展真实实验按授权范围执行。

准备状态与各阶段日志保存在`reports/`；应检查其中的状态、时间及来源摘要，不能把代码存在等同于流程完成。本文也不提供虚构的模型分数或提升比例。真正的执行状态以带时间和来源的JSON报告为准。
